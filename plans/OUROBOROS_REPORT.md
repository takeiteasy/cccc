# CCCC Inside CCCC — Compatibility Report

> Date: 2026-06-07  
> Tester: OpenCode  
> Goal: Attempt to compile CCCC's own source code with the CCCC compiler to surface missing C features, parser bugs, and header incompleteness.

## Executive Summary

**CCCC cannot currently compile its own source code out-of-the-box.**
The primary blocker is CCCC's embedded `Availability.h` compatibility stub, which defines `__has_builtin` and `__has_include` as object-like macros. This breaks Apple's system headers (and any headers that use these builtins in `#if` expressions) because the macro expansion turns expressions such as `__has_builtin(__is_target_os)` into `0(__is_target_os)`, which the parser rejects as a function call on an integer literal.

After working around that blocker (by supplying a local stub), the next issues are incomplete POSIX headers shipped with CCCC (`MAP_FAILED` missing from `<sys/mman.h>`, `isatty`/`fileno` missing from `<unistd.h>`) and a handful of missing C23/preprocessor features.

The attempt did **not** reach a link / run stage because of the `ffi.h` dependency (libffi is a system header, not embedded) and the `ops.c` inclusion model, but enough of the frontend was exercised to produce a detailed bug / gap list.

---

## Methodology

1. Start with the existing `./cccc` binary (built from the repo's Makefile).
2. Try to compile individual `src/*.c` files and, later, the full source set.
3. Use `-I./include` for CCCC's embedded standard library and `-i` for the macOS SDK when system headers are needed.
4. Record the first error for each file, categorise it, and create minimal reproducers.
5. Where a temporary workaround was needed (e.g. a local `Availability.h` stub), the workaround is noted so the finding is reproducible.

## 1. Critical Blockers

### 1.1 Embedded `Availability.h` breaks system headers that use `__has_builtin` / `__has_include`

**File:** `include/Availability.h` (embedded into the binary via `src/std.c`)  
**Impact:** **High** — blocks compilation of any source file that transitively includes system headers relying on these builtins (e.g. `<ffi.h>` → `<os/availability.h>` → `<AvailabilityInternal.h>`).

CCCC's stub contains:

```c
#ifndef __has_builtin
#define __has_builtin(x) 0
#endif
#ifndef __has_include
#define __has_include(x) 0
#endif
```

When a system header does:

```c
#if defined(__has_builtin) && __has_builtin(__is_target_os)
```

the preprocessor expands it to:

```c
#if defined(0) && 0(__is_target_os)
```

CCCC's constant-expression evaluator parses `0(__is_target_os)` as a function call on the integer literal `0`, yielding:

```
error: not a function
```

**Verification:**
```bash
echo '#if __has_builtin(__is_target_os)
#endif' | ./cccc -E -
# → error: not a function
```

**Note:** Even after editing the on-disk `include/Availability.h`, the compiled `cccc` binary continues to use the old version because the headers are baked into `src/std.c` (generated by `make stdlib`). Rebuilding CCCC with the system compiler is required to update the embedded copy.

---

### 1.2 `<ffi.h>` is not embedded

**Impact:** **High** — every CCCC source file includes `src/cccc.h`, which unconditionally includes `<ffi.h>` (libffi). CCCC does not ship an embedded `ffi.h`, so compilation fails immediately unless the system `ffi.h` is provided. Providing the system `ffi.h` in turn triggers blocker 1.1.

**Workaround attempted:** Create a local minimal `ffi.h` stub. This is feasible for a full self-hosting attempt but requires manually replicating libffi's public API (types `ffi_cif`, `ffi_type`, macros `FFI_DEFAULT_ABI`, `FFI_FN`, functions `ffi_prep_cif`, `ffi_call`, etc.). This was not pursued to completion because blocker 1.1 already demonstrates a fundamental compatibility issue.

---

### 1.3 `ops.c` is not compiled as a separate translation unit

**File:** `src/ops.c`  
**Impact:** Medium — `Makefile` explicitly filters `src/ops.c` out of `SRCS` because `src/vm.c` contains `#include "ops.c"`. If a user naïvely passes `src/*.c` to CCCC, `ops.c` would be compiled twice, causing duplicate-definition errors. A self-hosting build script would need to mimic the Makefile's filter logic.

## 2. Missing / Incomplete Embedded POSIX Headers

These were found **after** supplying a local `Availability.h` stub that does **not** define `__has_builtin` / `__has_include`.

### 2.1 `MAP_FAILED` missing from `<sys/mman.h>`

**File:** `include/sys/mman.h`  
**Impact:** Medium — `src/arena.c` uses `MAP_FAILED`.

```bash
echo '#include <sys/mman.h>
int main(){ return MAP_FAILED == 0; }' | ./cccc -I./include -
# → error: undefined variable 'MAP_FAILED'
```

The POSIX value is `((void *) -1)`. Adding it to the stub allows `arena.c` to compile.

---

### 2.2 `isatty` and `fileno` missing from `<unistd.h>`

**File:** `include/unistd.h`  
**Impact:** Medium — `src/main.c` uses `isatty` and `fileno` (via macros `CCCC_ISATTY` / `CCCC_FILENO`).

```bash
grep -E 'isatty|fileno' include/unistd.h
# → no output
```

These are standard POSIX functions and should be declared.

## 3. Missing C Language / Preprocessor Features

All tests performed with the current `./cccc` binary on trivial standalone programs.

| Feature | Status | Evidence |
|---|---|---|
| `typeof` / `typeof_unqual` | **Supported** | `echo 'int main(){ typeof(int) x=42; return x; }' \| ./cccc -` → 42 |
| `_Generic` | **Supported** | `echo 'int main(){ return _Generic(1,int:42); }' \| ./cccc -` → 42 |
| `auto` type inference (C23) | **Supported** | `echo 'int main(){ auto x=42; return x; }' \| ./cccc -` → 42 |
| `static_assert` | **Supported** | Parsed correctly (not exercised in CCCC source directly) |
| `__VA_OPT__` | **Supported** | Used by CCCC's own preprocessor |
| `#embed` (top-level) | **Supported** | Produces comma-separated integer literals |
| `#embed` inside initializers | **Not supported** | `echo 'int d[]={#embed "f"};' \| ./cccc -c -` → *expected an expression, found '#'* |
| `#warning` | **Not supported** | Silently ignored / no diagnostic output |
| `nullptr` (C23) | **Not supported** | `echo 'int main(){int*p=nullptr;}' \| ./cccc -` → *undefined variable 'nullptr'* |
| `_BitInt(n)` (C23) | **Not supported** | `echo 'int main(){_BitInt(8)x=0;}' \| ./cccc -` → *expected ';'* |
| `[[nodiscard]]` / `[[maybe_unused]]` on functions | **Not supported** | `echo '[[nodiscard]] int f();' \| ./cccc -c -` → *variable name omitted* |
| `__attribute__((unused))` on vars / fns | **Partially supported** | Works on structs (`packed`, `aligned`), rejected on functions/variables |
| `__has_include` in `#if` | **Not supported** | Treated as undefined macro → replaced by `0` → `0(<file>)` → *not a function* |
| `__has_builtin` in `#if` | **Not supported** | Same failure mode as `__has_include` |
| `__has_c_attribute` in `#if` | **Not supported** | Same failure mode |
| `__has_embed` in `#if` | **Supported** | Native implementation in preprocessor |

## 4. Parser / Semantic Bugs

### 4.1 `__attribute__((unused))` on local variables rejected

```bash
echo 'int main(){ __attribute__((unused)) int x=1; return x; }' | ./cccc -
# → expected an expression, found 'int'
```

This suggests the parser does not accept GNU-style attributes in the local-variable declaration position, despite the README listing `unused`/`maybe_unused` as supported.

---

### 4.2 `[[...]]` attributes rejected before function definitions

```bash
echo '[[maybe_unused]] int f(){return 1;}' | ./cccc -c -
# → variable name omitted
```

CCCC only recognises `[[cccc::macro]]` / `[[cccc::comptime]]` in specific contexts; general C23 attribute placement is not implemented.

---

## 5. What *Did* Work

- **Core C11**: `int main(){ return 42; }`, structs, unions, enums, bit-fields, designated initialisers, compound literals, flexible array members.
- **GNU extensions**: `typeof`, `__attribute__((packed))`, `__attribute__((aligned(N)))` on structs.
- **Preprocessor**: `defined`, `__has_embed`, `#if` with integer expressions, `#ifdef`, `#ifndef`, `#pragma once`, variadic macros with `__VA_OPT__`.
- **Auto type inference**: `auto x = 42;` works as a C23-style placeholder.
- **Single-file compilation**: After removing `ffi.h` and adding `-DMAP_FAILED='((void*)-1)'`, `src/arena.c` compiles to bytecode successfully (`./cccc -c src/arena.c`).

## 6. Recommendations

### Immediate (fix blockers)

1. **Fix `Availability.h`** — Do **not** define `__has_builtin` or `__has_include` as macros. Instead:
   - Implement native `__has_include` evaluation in the preprocessor (`read_const_expr` in `preprocess.c`).
   - Implement native `__has_builtin` evaluation (or at least leave it undefined so `#if defined(__has_builtin)` is false).
   - Regenerate `src/std.c` (`make stdlib`) and rebuild.

2. **Complete `<sys/mman.h>`** — Add `#define MAP_FAILED ((void *) -1)`.

3. **Complete `<unistd.h>`** — Add declarations for `int isatty(int fd);` and `int fileno(FILE *stream);`.

### Short-term (missing features)

4. **Implement `__has_include` in `#if`** — It is widely used in modern system headers and is essential for macOS/iOS compatibility.

5. **Implement `#warning`** — GCC/clang compatible, trivial to add.

6. **Extend attribute support** — Allow `[[nodiscard]]`, `[[maybe_unused]]`, and `__attribute__((unused))` on functions and variables. This is needed for compatibility with code that uses these.

7. **Support `#embed` in initializers** — The standard permits it; CCCC currently only supports it as a top-level token sequence.

### Medium-term (C23 gaps)

8. **`nullptr`** — Add the C23 null-pointer constant.
9. **`_BitInt(n)`** — Add support for the C23 arbitrary-width integer type.
10. **`__has_c_attribute`** — Add to the preprocessor expression evaluator.

### Long-term (self-hosting path)

11. **Embed or stub `<ffi.h>`** — Since libffi is required for the VM's FFI path, consider shipping a minimal `ffi.h` stub that matches the subset CCCC actually uses (`ffi_cif`, `ffi_type`, `ffi_prep_cif`, `ffi_call`, etc.). This removes the dependency on system libffi headers.

12. **Document the `ops.c` inclusion model** — Make it explicit in `AGENTS.md` or `README.md` that `src/ops.c` is not a standalone compilation unit.
