# CCCC and C++

Where CCCC's features behave like their C++ counterparts and where they differ. This page compares semantics, not syntax. CCCC stays C: no classes, no overloading of functions, no implicit constructors or destructors, no exceptions.

| C++ feature | CCCC counterpart | Same idea | Main difference |
|---|---|---|---|
| Class and function templates | [`@template`](templates.md) | Instantiate per argument list, specialise, packs, defaults | Function templates deduce their arguments from a call and operator templates from their operands; struct, union, enum and typedef templates take explicit arguments; no constraints or overloads |
| Operator overloading | [`[[cccc::operator]]`](operators.md) | `a + b` calls a user function | Free functions bound by attribute; exact operand types; fewer operators |
| Member functions | [`[[cccc::method]]`](methods.md) | `s.f(x)`, `T.f(x)` | Statically dispatched, explicit receiver, no `this`, no inheritance; a `static` member is called through the type |
| `constexpr`, `consteval`, `if constexpr` | [`@comptime`](macros.md) | Code runs during compilation | Runs arbitrary C and builds syntax trees; not part of the type system |
| Static reflection (`^^`) | [`^^name`](macros-reflection.md) | `^^` yields a compile-time handle | Handle is a compiler object (`Type *`, `Obj *`) |
| Defaulted special members, `<=>` | [`@equals`, `@compare`, `@ctor`, ...](derive.md) | Compiler generates `==`, ordering, construction | Generated by attribute on request, never implicitly |
| RAII, destructors | [`cleanup`](attributes-cleanup.md), [`@destroy`](derive-owned.md) | Scope-exit release | Per variable and opt-in; assignment is a plain copy |

## Templates

A template is a pattern that becomes a real type or function per argument list. Both languages instantiate on first use, share one instance per list and keep unused templates out of the program.

| | C++ | CCCC |
|---|---|---|
| Arguments | Deduced from a call (`max(1, 2)`) | Function templates: deduced from a call, `max(1, 2)`, or written, `max@(int)(1, 2)`[^spelling]; type templates: written, `Vec@(int)` |
| Parameter kinds | Types, constants, templates (template template) | Types and constants: integers, `float`, `double`, function and object pointers |
| Defaults | Yes | Yes, last, and may name earlier parameters |
| Packs and folds | `Ts...`, `sizeof...`, fold expressions | Same, see [templates-variadic.md](templates-variadic.md) |
| Specialisation | Full, and partial for classes | Full and [partial](templates.md#partial-specialization) for structs, unions, enums and typedefs |
| Overloads | Many functions share one name | One template per name; a function name is one function |
| Constraints | Concepts, SFINAE, `requires` | None |
| Checking | Names and syntax at definition, the rest at instantiation | Tokens only until instantiation |
| Instance name | Mangled by the compiler | Plain C name you can write: `Vec_int`, `max_int` |
| Linkage | Inline: one definition across files | Shared weak symbol; `static` template gives a private copy per file |

### Instantiation is textual

The body is kept as tokens. A template that is never used is never compiled, and an error in an instance is reported at the template body with the instantiation site:

```c
@template(T) int f(void) { T x; return x.nope; }   // fine until f@(int)() is used
```

C++ checks non-dependent names at definition; CCCC checks everything at instantiation. In both, using an operator the argument lacks is a compile error, but CCCC has no way to select another candidate: there is no SFINAE, so a failed instance is an error, not a skipped overload.

### Instances are named C types

An instance is an ordinary C name, so the generated code is usable from C, from other tools and from derive attributes:

```c
@template(T)
@equals
struct Cell { T a, b; };
@inst(int) Cell x = {1, 2}, y = {1, 2};
_Bool same = Cell_int_equals(&x, &y);     // name derived from the instance
```

Two arguments that name the same type (`size_t` and `unsigned long`) are one instance, as in C++. A tagged `struct P` and a typedef'd anonymous `P` are different instances.

### Specialisation

An exact `@specialize` wins, then the most specialised matching partial, then the template, as in C++. A specialisation replaces the whole body, and template parameter names are not visible in it. It must come before the first use of its arguments.

## Operators

`[[cccc::operator(sym)]]` rewrites `a + b` into a call of the bound function when an operand is a struct or union. Like a C++ free operator, the function is an ordinary function that you can call by name.

| | C++ | CCCC |
|---|---|---|
| Where defined | Member or free function | Free function with the attribute, or a function in the struct body (named `T_operator_add`) |
| Selection | Overload resolution with implicit conversions | Exact operand types: `(Vec2, int)` and `(Vec2, Vec2)` can both exist, but `v + 5L` does not match `(Vec2, int)` |
| Operand passing | Any parameter types | Any, but at least one parameter is `T` or `T *` |
| Compound assignment | Separate `operator+=` | Uses the binary operator and evaluates the left side once |
| `++`, `--` | Own operators | Through `+` and `-` |
| Comparison | `==`, `<=>`, rewritten `!=`, `<`... | Same: `<=>` supplies `<`, `<=`, `>`, `>=`; `!=` is `!(a == b)` |
| Subscript | `operator[]` returns a reference | `[]` returns a pointer, and the parser dereferences it so `a[i]` is an lvalue |
| Evaluation order | Follows the built-in operator's rules for a few (`<<`, `>>`, `=`, `[]`), unspecified for the rest | Left operand before the right, always |
| Not overloadable | `::` `.` `.*` `?:` | Also `&&`, `\|\|`, `,`, `=`, unary `*` and `&`, `->` |
| Absent | | Call `()`, conversion operators, `new` and `delete`, user-defined literals |

`=` is never overloaded, so assignment is always a memberwise copy; deep copy is a function you call (`@clone`).

## Methods

`[[cccc::method(T)]]` makes `s.f(x)` a call of `f(&s, x)`.

| | C++ | CCCC |
|---|---|---|
| Receiver | Implicit `this` | First parameter, written out: `T *` or `T` |
| Dispatch | Static, or virtual with `virtual` | Always static; no virtual functions, no inheritance |
| Overloading | By parameter types | Keyed by (type, name): two functions with the same name for one type are an error |
| Name lookup | Members and functions share a scope | A data member named `f` wins over a method `f` |
| Layout | Unaffected by non-virtual methods | Unaffected: a method adds no member |
| Access control | `public` / `private` | None |
| Function pointer member | A data member | A data member; calling it is not a method call |
| Definition | In the class, or out of line as `T::f` | In the struct body or free with the attribute; the function is also callable by name (`Vec2_len(&v)`) |

An rvalue receiver (`make().len()`) passed to a `T *` parameter is copied into a temporary, so writes through the pointer are discarded.

### Templates and members

A method or operator written in a struct template's body belongs to every instance; the receiver is `struct Vec2 *`, as the template name stands for the instance. An operator written once as a function template is instantiated from its operands, so `a + b` over a `Vec2@(int)` makes `vadd_int`:

```c
@template(T) struct Vec2 {
    T x, y;
    T dot(const struct Vec2 *self, const struct Vec2 *o) { return self->x * o->x + self->y * o->y; }
    struct Vec2 operator-(struct Vec2 a) { return (struct Vec2){-a.x, -a.y}; }
};
@template(T)
[[cccc::operator(+)]]
@inst(T) Vec2 vadd(@inst(T) Vec2 a, @inst(T) Vec2 b) {
    return (@inst(T) Vec2){a.x + b.x, a.y + b.y};
}
```

## Compile-time evaluation

| | C++ | CCCC |
|---|---|---|
| What runs | A restricted subset of C++ (`constexpr`, `consteval`) | Any C, in the VM, during compilation |
| Result | A value | A value, or syntax: a `Node *` replaces the call, or a declaration is emitted |
| Trigger | Constant expression contexts, `if constexpr` | A call to a `@comptime` function |
| Side effects | None | Allowed, within the [comptime policy](comptime-policy.md) (files, network and the like are denied by default) |
| Type safety | Results are typed values | Results are code, checked when it is parsed into the program |
| Metaprogramming | Templates, `constexpr` recursion | `@comptime` code builds and walks the AST ([macros-builders.md](macros-builders.md)) |
| `if constexpr` | Discards the untaken branch | None; fold the condition in a `@comptime` function and return the branch you want |
| Constant objects | `constexpr` variables and functions | C23 `constexpr` objects only; no `constexpr` functions |
| Reflection | `^^T`, splices, `std::meta` queries | `^^name` gives a `Type *` or `Obj *` to `@comptime` code, which queries and builds with the [reflection builtins](macros-reflection.md) |

### A call-site macro

A `@comptime` function replaces its call with the returned syntax. It runs arbitrary code first:

```c
@comptime Node *square(Node *x) { return Quote("($1) * ($1)", x); }
int n = square(2);              // (2) * (2)
```

A C++ `constexpr` function computes a value of its declared type. A `@comptime` function chooses the code that appears at the call, so one call can become a statement, a loop or a whole function. The result goes through the normal parser and type checker.

### Templates in comptime

`@comptime` code can instantiate runtime templates (`InstantiateType`, `InstantiateFunction`) and has templates of its own, apart from the program's. See [macros-templates.md](macros-templates.md).

## Generated members and lifetime

C++ generates copy, move and destructor members implicitly, and `= default` requests `==` and `<=>`. CCCC generates nothing unless an attribute asks.

| | C++ | CCCC |
|---|---|---|
| Constructor | Member function run on definition | `@ctor` makes `T_new(...)`, called explicitly; `T x;` runs nothing |
| Default member values | In-class initialisers | `T m = expr;` or `@default(expr)`: the value `T_new` gives the member |
| Equality | `bool operator==(...) const = default;` | `@equals`: `T_equals`, and `==` and `!=` are bound |
| Ordering | `auto operator<=>(...) = default;` | `@compare`: `T_compare`, and `<=>`, `<`... are bound; `@compare_order(N)` and `@compare_desc` shape it |
| Hash | `std::hash` specialisation | `@hash` |
| Copy | Implicit copy constructor, deep for owning types | Assignment copies bytes; `@clone` makes `T_clone`, deep for `@owned` members |
| Destructor | Runs at scope exit | `@destroy` makes `T_destroy`; call it, or register it with `cleanup` |
| Scope-exit release | RAII on every object | `cleanup(fn)` on a variable, run in reverse order on every exit path from the scope |
| Moves | Move constructors, `std::move` | None |
| Exceptions | Unwinding runs destructors | None; `cleanup` runs on `return`, `break`, `goto` and block exit |
| Serialisation | Library | `@to_json`, `@from_json`, `@serialize`, ... |

```c
@equals
@compare
@ctor
struct Version { int major, minor; };

struct Version a = Version_new(1, 2), b = Version_new(1, 3);
_Bool older = a < b;      // Version_compare(&a, &b) < 0
_Bool same  = a == b;     // Version_equals(&a, &b)
```

A derived function applies to a template instance and carries its mangled name (`Cell_int_equals`).

### Ownership

C++ ties ownership to the type through constructors, destructors and move semantics. CCCC records it on members: `@owned` marks a pointer as heap memory, and `@clone` and `@destroy` use that mark. A pointer without it is copied as a pointer. The compiler does not call `T_destroy` for you, so a missed call is a leak. With the [safety levels](safety.md) on (`-1` and above), leaks are reported at run time.

## Safety and undefined behaviour

| | C++ | CCCC |
|---|---|---|
| Out-of-bounds, use-after-free | Undefined behaviour | Reported by the VM at [`-2` and `-3`](safety.md); level `-0` and a `-c=native` build have no checks |
| Bounds in the type | `std::span`, `std::array` | [Checked pointers](safety-checked-pointers.md): `count(n)` on a pointer declaration |
| Signed overflow | Undefined | Reported at `-1` and above ([safety-overflow.md](safety-overflow.md)) |
| Strings and arrays | Library types | Plain C arrays and pointers |

## Things CCCC leaves out

No classes or inheritance, function or operator overloading beyond operand-type selection, references (`T &`), namespaces, default function arguments in the C++ sense (`@default` on a parameter is the nearest, see [derive.md](derive.md)), lambdas (blocks and GNU nested functions are the nearest), `auto` return types, `std` containers, exceptions, RTTI and `virtual`.

[^spelling]: The prefix `@inst(int) max`, the postfix `max@(int)` and the keyword `__inst(int) max` name the same instance; see [templates.md](templates.md#spellings).
